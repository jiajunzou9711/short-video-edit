# 每日文章视频

这是通用 agent 工作流，不依赖特定模型厂商或产品。首次安装/配置或更新读取 [安装规程](references/INSTALL.md)，使用本 skill 的 `scripts/setup.py`；ASR 细节见 [ASR_SETUP.md](references/ASR_SETUP.md)。安装后所有命令中的 `<venv-python>` 均使用安装器返回的虚拟环境 Python 绝对路径，不使用系统 `python3`；以用户指定的媒体工作区为根；脚本为本 skill 的 `scripts/pipeline.py`；每期目录 `output/daily-video/<视频名>`，同名不同输入使用新目录。用户给路径即执行，不启动定时监听。schema 与故障处理见[工作流参考](references/WORKFLOW.md)，仅在需要时读取对应段落。

## 不变约束

- 小红书停在最后“发布”前，只有用户明确放行本次发布才可点击；禁止活动关联，包括平台自动关联。视频号固定手动上传，不访问或绕过被安全策略禁止的后台。
- 两平台共用一个MP4和一张 `cover.jpg`（1080×1440、3:4、标题默认上方水平居中，两侧留白避开发布时间提示与右上角播放按钮）；保留原视频画幅，不加美颜滤镜，不插入无声封面开场。居中布局仍需在实际平台小图预览中核对，避免遮脸及按钮重叠。
- 封面必须通过两项人工视觉检查：①人物表情自然，优先正视镜头、眼睛睁开、嘴部平稳的瞬间，排除眨眼、说话中嘴形扭曲、夸张手势和运动模糊；从多个候选帧中选，不机械使用默认时间。②肤色、衣服和背景与原片正常播放时一致，不发白、发灰、过曝或异常偏色，不加滤镜、美颜或审美调色。原尺寸和平台小图都要看，平台自动“质量通过”不能代替这两项检查。
- HDR（HLG/PQ）原片不能直接用未做正确色彩管理的普通抽帧当最终封面。macOS 优先用 `AVAssetImageGenerator` 的 `.forceSDR` 原生导出，再依据源图 ICC 转为 sRGB 并嵌入输出 ICC；这是保持显示一致的必要转换，不是风格调色。具体操作按[工作流参考](references/WORKFLOW.md) 的“封面表情与色彩”段落执行，不用提亮、降饱和度等手调去补偿错误抽帧。
- HDR成片转换与封面转换分别检查。主脚本尚未自动做HDR→SDR色调映射；需转换时按[工作流参考](references/WORKFLOW.md)的“HDR成片转换”段落，优先将原片转为Rec.709 SDR再合成字幕/解释框。保留source.json的原视频路径与hash，另记实际渲染输入，并对最终交付文件重新check，不能用封面正常代替成片色彩验证。
- 科学术语、人名、数字及解释框中英文对照核对原文；无法由原文解决的疑点查权威一手来源。不能用PDF虚构口播或悄改实质错误，不确定的重要内容才问用户。
- 摘要聚焦本期内容，不强行提及刊物名称。解释框按下节选择口播中已出现的术语，补充简明、准确的解释；区分定义、研究结果、理论主张、推测和物种边界。

## 解释框规则

- **选词紧贴口播。** 只解释用户实际说过、但一带而过或未讲清楚的名词、短语、现象；在其首次需要解释的位置出现。标题直接使用该词及准确英文，不写成长设问或观点句。不能因为查到相关研究，就新增口播没有提到的概念作为卡片标题。
- **补足含义，不另起话题。** 补充该词的定义、机制、引申义或适用边界，帮助理解正在讲的内容。已经讲清楚的不重复；不展开与当前口播无直接关系的背景、研究进展或争论，避免形成另一条叙事、让观众在听口播和读卡片之间分心。数量按实际需要决定，不凑卡片。
- **正文采用维基百科式文风。** 客观、直接、完整地说明“是什么”及必要细节，语言通俗，精炼而准确。避免设问、反问、劝导、口号和含混的概括；不用堆砌术语制造信息增量。原文不足以支持补充解释时，查权威一手来源并记入 `checked_sources`。理论结论标明其前提，不能把推测写成定论；实质口播错误显式标注更正，不悄改成用户没说过的话。
- **先压字数，再谈占位。** 正文默认约30–40个中文字符、1–2句，按实际字体测量，以两行正文为目标；英文词按实际宽度计算。保留必要限定，不为凑字数牺牲准确性。超长时先精简或拆分含义，不能靠缩小字号塞入大段文字。1080×1920成片可参考已验收模板：正文35–38字、45px（`annotation_scale: 1.0`）、两行，整卡约占画面高度15%；其他画幅按构图调整，不机械套数值。
- **胸前放置，保持清晰。** 深色半透明卡、浅蓝标题/左条、灰英文、白解释。允许轻微遮到下巴，避免遮住眼睛、嘴部或大面积脸部；不为完全避开下巴而缩小文字，也不把卡片移到头顶来回避布局冲突，那里可能与小红书图标重叠。上述竖屏模板显式设置 `annotation_y_fraction: 0.50`、`caption_y_fraction: 0.70`；每期核对构图、双行字幕间隔和底部25%的平台UI区，必要时微调胸前位置。每张约10–12秒，不相互重叠，并查看正常手机尺寸下的效果。
- 用户要求先审文案时，先提供“口播位置、标题、正文”，获其明确通过后再渲染；已有审核通过的文字按批准版本执行。

示例（仅在口播确实提到该词时使用）：**深度学习 · Deep learning**——“深度学习利用多层神经网络学习数据特征，通过训练调整连接权重，完成预测等任务。”

## 执行

1. `<venv-python> <脚本> prepare <视频绝对路径> <本期目录>`：检查音轨、豆包语音录音文件识别极速版字级转写、静音候选、抽样帧。`work/pause-candidates.json`按字级间隔列出全部≥0.9秒停顿，`acoustic_silence`低于0.5的为仅ASR候选，须审听后再决定；`suggested-cuts.json`只含声学确认的。HDR输入会提示，注意封面与预览色彩。凭据从使用者本机的 `~/.config/volc.env` 或 `VOLC_CONFIG_FILE` 指定位置读取，支持安全注入的环境变量；先运行 `setup.py doctor` 检查，缺少配置时按 [ASR_SETUP.md](references/ASR_SETUP.md) 引导使用者本机填写；不打印密钥。静音输入需带声音原片/同步录音。同一期返工复用work内ASR，不重复调用识别。
2. 通读完整 `work/transcript.txt`、静音候选和输入抽样帧；若本期解读文章，定位对应PDF并读取相关完整文章；若是本人观点口播，记录此来源，不虚构PDF或研究依据。PDF操作优先使用环境中可用的 PDF skill 或 PDF 读取工具。只按需读取字级时间戳片段，避免输出整个ASR JSON。字幕逐条校对，疑点提取短音频审听；无音频能力就如实记录未审听。
3. 写 `editorial.json`：原视频时间的captions/cuts/annotations、cover_title/cover_time、两平台文案、source_evidence/review_notes，完成实质校对才设reviewed:true。annotations遵循“解释框规则”，逐张核对口播锚点、信息增量、正文行数及实际布局。每期检测长停顿，约1秒以上空白为候选，结合声学静音、ASR无口播区间和上下文自主剪除，通常两侧各留0.2秒；保留呼吸/强调，不截词。字幕最多两行，按字级时间断句，不拆英文，不均匀伪造时间戳。
4. `<venv-python> <脚本> render <本期目录>`，再 `<venv-python> <脚本> check <本期目录>`。editorial.json在render后改动过，check会拒绝，须重新render。check合并完整解码、时长/音轨存在性检查、开头/中段/结尾、每个解释框及每处剪切两侧抽帧，生成work/qa-contact-sheet.jpg、qa-check.json和两平台文案。查看拼图及cover.jpg，核对字幕、解释框、脸部、溢出、切点和音画同步，并完成上述封面表情与色彩两项检查；拼图过小或疑点再看原尺寸帧/短片段。HDR封面若仍由普通FFmpeg抽帧生成，须按专用操作替换为通过色彩检查的版本再上传。技术检查不等于音频审听或视觉通过，不假称验证。
5. 用户明确要求仅本地制作或返工时，跳过浏览器与上传，记录本地新版与平台已有旧版的区别；否则小红书发布前准备的完成标准是：页面已填好所有适用发布信息，只差用户点击最后“发布”，不能只交付本地成品或停在上传完成。登录检查优先复用已有创作页；若只有已登录的小红书主页，读取主页“发布”链接并进入其完整地址，待页面加载后核对账号。不要仅凭直开后台根地址跳到 `/login` 就要求用户重新登录；只有正式发布入口也明确要求认证时才请求用户处理。检查实时登录账号，上传同一成品视频与cover.jpg；按浏览器要求读file-uploads文档。填好标题、摘要/正文和少量正式话题，从平台候选中选择，避开标为“活动话题”的标签。根据本期内容自主选择一个相关的已发布视频作“引用笔记”链接，并加入一个最合适的已有合集；不照搬上一期选择，不创建新合集，没有相关项则如实说明。检查原创声明及其他适用声明，真实的本人出镜解读可声明原创；接受须知时遵守工具的当次确认规则，不虚构地点、日期或内容来源。无需为凑齐字段添加无关地点、群聊、投票、路线或营销组件。上传完成后核对标题、正文、正式话题、引用笔记、合集、原创声明、共用封面小图及活动未关联，取消任何自动关联活动。自动章节若使用须校对后应用，不能保留未核对的自动内容。重上传时使用不同文件名触发更新，并重查可能被重置的声明和设置。最终保留发布前页面，绝不点击“发布”。
6. 写publish-status.json：小红书awaiting_user_publish（实际上传文件路径/hash、标题/话题、所选引用笔记和合集、声明与未关联活动状态、最终截图），视频号manual_upload_ready（相同视频/封面和专用文案路径）。hash可复用qa-check.json，仅当文件未变；保存截图并保留发布前页面。状态不确定先核查，不盲目重传。

## 减少重复用量

正常每日运行仅按需读取脚本和工作流，不重复读取历史任务，不重复查询已经确认的服务配置；仅加载当前步骤需要的schema或故障段落。读取完整转写和完整相关文章仍必须保留；重复信息只读一次。

独立读取批量进行，命令输出摘要/错误即可；FFmpeg长日志保存本期work，不回传全文。上传后按实际进度合理间隔检查，不能密集轮询相同状态；必需实时页面检查仍执行。字幕、解释框等视频内容修改前先完成原文核对，再统一渲染、check、上传。仅更换封面且未修改 editorial.json 时，按 [工作流参考](references/WORKFLOW.md) 单独替换共用 cover.jpg、更新路径/hash并核对平台小图，无需重编码视频；修改 editorial.json 则仍须重新 render/check。只有缺陷或新增修改才重做受影响检查。每日处理视频不跑开发回归测试，修改代码时才跑；每条实际视频仍完成质量检查。

## 交付与清理

交付直接说明“小红书已上传准备好，你可以检查后点击最后的发布”，不是声称公开发布成功；附可打开的本地文件夹、最终视频、共用封面、视频号发布文案链接及页面截图。必须提醒：“两边上传发布成功后，回来告诉我‘清理’，我会删除本期全部本地生成产物和原视频。”交付时保留全部文件。

用户按约定回来说“清理”即确认上传成功并要求删除本期产物及对应原视频；若明确某平台未成功则保留。执行 `<venv-python> <skill-dir>/scripts/finalize.py <本期目录> --purge --uploads-confirmed --delete-original` 预览（脚本按source.json路径与SHA-256核对原视频，不匹配则拒绝且不删任何东西；用户明确要求保留原视频时去掉 `--delete-original`），核对后加 `--apply` 删除原视频及整期目录，验证目录不存在，不留成品、缓存、截图或记录副本。不使用无--purge的旧模式代替。验证原视频及本期目录均不存在。源PDF保留；不得按文件名或通配符删除其他视频。始终保留skill、工作流、凭据及无关资料。完全清理后不可再交付旧链接或声称缓存仍在。

## 环境与首次使用

安装与依赖见 [安装规程](references/INSTALL.md)；安装后的处理脚本使用安装器返回的虚拟环境 Python。宿主没有浏览器能力时，交付本地文件并如实记录平台尚未准备，不声称已上传。详细参数、JSON schema、HDR 封面操作与故障处理按需读取 [references/WORKFLOW.md](references/WORKFLOW.md)。默认使用 macOS 中文字体，其他系统可通过 `DAILY_VIDEO_FONT` 和 `DAILY_VIDEO_CARD_FONT` 指定字体。不得从这个公开模板推断任何使用者的账号、登录状态、文件上传权限或凭据已经配置。清理从媒体工作区执行；非默认输出目录显式传 `--output-root`，先预览再删除。
